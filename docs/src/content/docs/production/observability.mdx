---
title: Observability
description: Hooks for logging retries and terminal errors without coupling to a logger.
---

The SDK exposes four optional hooks on `PoliPageClient.Builder`: `onRequest`, `onResponse`, `onRetry` and `onError`. They give you the raw signal needed to instrument the SDK with whatever logger or tracing library you use, without baking a dependency into the SDK itself. The SDK does not log on its own.

## The hooks

- `onRequest(Consumer<RequestEvent>)` — fires before each API attempt, retries included. `event.method()`, `event.url()`, `event.attempt()`.
- `onResponse(Consumer<ResponseEvent>)` — fires after each 2xx API answer, once its body is read. `event.status()`, `event.requestId()`, `event.durationMs()` (body included). Error answers and transport failures do not fire it.
- `onRetry(Consumer<RetryEvent>)` — fires just before the SDK waits between attempts. `event.attempt()` is the attempt about to start (`2` for the first retry), `event.delay()` the wait, `event.statusCode()`, `event.reason()` (`"5xx"` / `"rate_limit"` / `"timeout"` / `"network_error"`).
- `onError(Consumer<Throwable>)` — fires once with each error a call is about to throw: an API error (after the retries, when it is retried), `network_error`, `timeout`, `aborted` and `DOWNLOAD_FAILED`. A cancelled async future completes with the JDK's `CancellationException` and does not fire it.

`onRequest`, `onResponse` and `onRetry` cover calls to the Poli Page API only. The PDF download from the presigned URL (`render().pdf`, `render().pdfStream`, `renderToFile`, `documents().downloadPdf`) is a single attempt outside the retry loop; only `onError` fires for it, when it fails.

The hooks run inline and synchronously: on the calling thread with the blocking facades; with the async facades they can run on an HTTP client thread instead. A hook that throws is caught and swallowed — a faulty hook will never break the request.

## Tracing

For OpenTelemetry, wrap the call site in a span and record the SDK's `RetryEvent` as span events. The blocking facade keeps you on the caller's thread; the async facade chains on whatever executor the future is completed on.

## Example

```java
import java.util.Map;
import page.poli.sdk.PoliPageClient;
import page.poli.sdk.input.RenderInput;

class Example {
    public static void main(String[] args) {
        PoliPageClient client = PoliPageClient.builder()
            .apiKey(System.getenv("POLI_PAGE_API_KEY"))
            .onRetry(event -> System.out.printf(
                "retry attempt=%d delay=%s reason=%s status=%s%n",
                event.attempt(), event.delay(), event.reason(), event.statusCode()))
            .onError(err -> System.err.println("terminal: " + err.getMessage()))
            .build();

        RenderInput input = RenderInput.builder()
            .project("billing")
            .template("invoice")
            .data(Map.of("invoiceNumber", "INV-001", "total", 1280))
            .build();

        byte[] pdf = client.render().pdf(input);
    }
}
```
