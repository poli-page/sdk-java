The Poli Page Java SDK authenticates every request with a bearer token. An API key belongs to exactly one environment of your organization, and the API resolves the environment from the key: the SDK never sends one.

## API keys

<ApiKeyCallout />

A key is `pp_{env}_{32 lowercase hex}`, where `{env}` names its environment, matching:

```text
^pp_(?=[a-z][a-z0-9-]{0,19}_)[a-z][a-z0-9]*(?:-[a-z0-9]+)*_[0-9a-f]{32}$
```

| Environment                           | Key            | Watermark | Counted |
| ------------------------------------- | -------------- | --------- | ------- |
| `sandbox` (every org)                 | `pp_sandbox_…` | yes       | no      |
| `live` (every org, deletable on Pro+) | `pp_live_…`    | no        | yes     |
| created on Pro+ (e.g. `staging`)      | `pp_staging_…` | no        | yes     |

"Counted" means the render counts toward the organization's monthly PDF quota. `sandbox` documents expire 30 days after creation. There is no watermark option: a template that wants a watermark outside `sandbox` uses the `poli-watermark` class. Standard and service keys share this one format. The SDK only checks that the key is not blank.

Pass the key to the client builder:

```java
PoliPageClient client = PoliPageClient.builder()
    .apiKey(System.getenv("POLI_PAGE_API_KEY"))
    .build();
```

The SDK never reads `POLI_PAGE_API_KEY` from the environment implicitly. You always pass the key in.

## Example

```java
import page.poli.sdk.PoliPageClient;

class Example {
    public static void main(String[] args) {
        PoliPageClient client = PoliPageClient.builder()
            .apiKey(System.getenv("POLI_PAGE_API_KEY"))
            .build();
    }
}
```
